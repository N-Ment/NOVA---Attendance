# NOVA HR · เวอร์ชัน 5

โครงสร้าง: Google Sheets เป็นฐานข้อมูล, Apps Script เป็น API, `public/` เป็นหน้าเว็บสำหรับ Netlify และ GitHub ใช้เก็บซอร์สโค้ด

## ติดตั้งหรืออัปเกรด

1. เปิด Google Sheet `Nova.3` → **ส่วนขยาย → Apps Script**
2. ใส่ไฟล์ `.gs` ทั้ง 8 ไฟล์ใน `apps-script/` ลงในโปรเจกต์ Apps Script เดียวกัน: `Setup.gs`, `Util.gs`, `Code.gs`, `Attendance.gs`, `Leave.gs`, `Users.gs`, `Face.gs`, `Calendar.gs` แล้วบันทึก
3. เรียก `setupAll()` จาก Apps Script editor และอนุญาตสิทธิ์ ฟังก์ชันนี้สร้างชีตที่ขาดให้อัตโนมัติและรันซ้ำได้
4. ตรวจชีต `FaceTemplates`: คอลัมน์ **เวกเตอร์ใบหน้า (128 ค่า JSON)** จะมีข้อมูลเมื่อ Admin ลงทะเบียนสำเร็จ เวอร์ชัน 5 พยายามย้ายเวกเตอร์เดิมจาก Script Properties ของ **โปรเจกต์ Apps Script เดิม** ไปชีตนี้ขณะรัน `setupAll()` หากใช้โปรเจกต์ใหม่หรือเวกเตอร์เดิมหาย ต้องลงทะเบียนใบหน้าใหม่
5. Deploy Apps Script เป็น Web App โดยเลือก **เรียกใช้ในฐานะ: ฉัน** และ **ผู้มีสิทธิ์เข้าถึง: ทุกคน** เมื่อแก้โค้ดเดิมให้สร้างเวอร์ชัน Deploy ใหม่ คัดลอก URL `/exec`
6. นำเนื้อหา `public/` ขึ้น Netlify (`netlify.toml` กำหนด publish directory ไว้แล้ว) ตั้ง URL `/exec` ในหน้าเข้าสู่ระบบ หรือใน `public/js/config.js` ก่อนเผยแพร่ ห้ามใส่ PIN หรือ token ในไฟล์นี้

`setupAll()` สร้าง Users, Accounts, FaceTemplateIndex, **FaceTemplates**, CalendarDays, Attendance, Config, Shifts, LeaveTypes, LeaveRequests, AuditLog และชีตประกอบอื่น ๆ โดยไม่ลบแถวที่มีอยู่ PIN ครั้งแรกของ OWNER อยู่ในบันทึกการดำเนินการของ `setupAll()` หาก PIN หายให้เรียก `resetOwnerPin()` ใน editor

## การสแกนและลงเวลา

- เปิดเว็บแล้วพบหน้าสแกนทันที กล้องจะพยายามเปิดเอง หากเบราว์เซอร์ขอการกดจากผู้ใช้ ให้กด **เริ่มสแกนใบหน้า**
- เมื่อเปิดกล้อง ระบบนับถอยหลังก่อนเริ่มตรวจใบหน้า ค่าเริ่มต้น **5 วินาที** และ OWNER ปรับได้ 0–15 วินาทีในหน้า **ตั้งค่าระบบ → LOCATION** เมื่อสแกนทั้งหน้าแรกและหน้าสแกนหลังล็อกอิน ระบบเทียบเวกเตอร์กับ `FaceTemplates` แล้วแสดงชื่อเล่นให้ตรวจ กด **ใช่ ฉันเอง** จึงบันทึกเข้างานหรือออกงาน; กด **ไม่ใช่ · สแกนใหม่** จะไม่บันทึกและเปิดกล้องใหม่ รายการยืนยันมีอายุ 2 นาทีและใช้ได้ครั้งเดียว หลังบันทึกสำเร็จกรอบภาพเป็น **สีเขียว** และมีเสียงบี๊บ เมื่อไม่สำเร็จกรอบเป็น **สีแดง** พร้อมข้อความสาเหตุ
- สแกนใบหน้าได้ตลอด **24 ชั่วโมง** ตามเวลา Asia/Bangkok และสแกนได้หลายรอบในหนึ่งวัน ระบบสลับ **เข้า → ออก → เข้า → ออก** โดยแต่ละคู่เก็บเป็นรายการแยกใน Attendance การออกงานข้ามเที่ยงคืนปิดรายการที่เปิดค้างอยู่
- `setupAll()` ซ่อมคอลัมน์ **สาย (นาที)** ของแถวเดิมที่เป็น `#NUM!` หรือค่าว่าง โดยคำนวณจากเวลาเข้าและกะ และกำหนดรูปแบบตัวเลขเป็นจำนวนเต็ม
- เวลาสายเก็บเป็นจำนวนเต็มนาที: ถ้าไม่สายเป็น `0` ถ้าช้ากว่าเวลาเริ่มกะให้นับนาทีที่เกิน ไม่มีการหักนาทีผ่อนผันในเวอร์ชัน 5
- ระบบพูด **ชื่อเล่นที่เป็นภาษาไทยเท่านั้น** หลังยืนยันและบันทึกสำเร็จ: ก่อน 09:00 “คุณ[ชื่อเล่น] ยินดีต้อนรับ”; ตั้งแต่ 09:00 “คุณ[ชื่อเล่น] เข้างานสายนะครับ”; เมื่อออก “คุณ[ชื่อเล่น] ออกงาน บ๊ายบาย” เลือกเสียงไทยผู้ชายจากเสียงที่อุปกรณ์มี หากชื่อเล่นไม่มีอักษรไทยจะใช้ส่วนภาษาไทยของชื่อเต็ม และหากไม่มีชื่อภาษาไทยเลยจะพูดเฉพาะข้อความสถานะ และลดความเร็วให้อ่านชัด หากอุปกรณ์ไม่มีเสียงไทยผู้ชาย ระบบใช้เสียงไทยที่มีพร้อมปรับโทนให้ต่ำลง กด **เปิดเสียงบนเครื่องนี้** หากเบราว์เซอร์ยังไม่อนุญาตเสียง
- โมเดลใบหน้าจะโหลดล่วงหน้าและใช้ตัวอย่างใบหน้า 1 ครั้งสำหรับการลงเวลา (ลงทะเบียนยังใช้ 2 ครั้ง) Apps Script แคชรายการใบหน้าชั่วคราว 5 นาทีและล้างแคชเมื่อข้อมูลพนักงานหรือใบหน้าเปลี่ยน
- หากหน้าสแกนไม่ได้ใช้งาน 30 วินาที ระบบแสดงนาฬิกาดิจิทัลแบบสมาร์ทวอชเต็มพื้นที่หน้าเว็บ แสดงเวลาและวันที่ไทยแบบสด แตะเพื่อกลับมาสแกน ระหว่างกำลังสแกนหรือรอยืนยันตัวตนจะไม่พักหน้าจอ การพักนี้ไม่สั่งปิดจออุปกรณ์ และเบราว์เซอร์ยังควบคุมการแสดงแถบเครื่องมือของตน

- OT อัตโนมัติ 1.5x เริ่มนับจาก **เวลาสิ้นสุดกะ** ในชีต Shifts (เช่น กะ 09:00–18:00 เริ่ม OT หลัง 18:00) เวลาเข้าก่อนเริ่มกะไม่สร้าง OT โดยตัวเอง OWNER/Admin ยังแก้นาทีสาย กะ และชั่วโมง OT ทุกอัตราในรายการลงเวลาได้โดยไม่มีเพดานชั่วโมงตามสูตรอัตโนมัติ การแก้ OT 1.5x จะปิดการคำนวณอัตโนมัติในแบบฟอร์มนั้น และต้องระบุเหตุผลเพื่อบันทึก AuditLog
- หน้าสแกนแรกแสดงนาฬิกาวงกลมพร้อมวันและเวลาปัจจุบันตามเวลาไทย

## Admin และพนักงาน

- OWNER เปลี่ยนชื่อบริษัทและอัปโหลดโลโก้ใน **ตั้งค่าระบบ → ชื่อและโลโก้บริษัท** ภาพถูกย่อก่อนเก็บใน Config และแสดงร่วมกันทุกเครื่อง
- ฟอร์มเพิ่มพนักงานเติมรหัส NV ตามลำดับให้อัตโนมัติ แต่ Admin พิมพ์แก้ได้ และเลือก **กะปกติ** ไว้เป็นค่าเริ่มต้น
- Admin ทุกคนกดชื่อใน **ตั้งค่าระบบ → EMPLOYEES** เพื่อดูข้อมูล ประวัติการลงเวลาและวันลา และแก้ชื่อ ชื่อเล่น แผนก กะของพนักงานได้ การแก้สิทธิ์ Admin ของหัวหน้าแผนกจำกัดเฉพาะ OWNER
- Admin ลงทะเบียนใบหน้าใน **FACE REGISTRATION** โดยเลือกพนักงานและสแกน ไม่ต้องติ๊กช่องรับทราบ หน้าพนักงานแสดงสถานะว่าเก็บใบหน้าสำเร็จหรือไม่ ก่อนลบเวกเตอร์มีหน้าต่างยืนยันและขอเหตุผล
- การลบพนักงานเป็นการปิดบัญชี ลบเวกเตอร์ใบหน้า และคงประวัติงานไว้
- Admin เปิดหน้าหลักแล้วเห็นภาพรวมพนักงาน ประวัติการลงเวลา และวันลาทั้งหมดโดยไม่ต้องเปิดแต่ละรายการ หน้า **ประวัติและรายงาน** แสดงฟอร์มแก้ไข 22 หัวข้อของรายงาน โดยแก้วันที่ เวลา กะ นาทีสาย หมายเหตุ และแยก OT 1.0/1.5/2.0/3.0 พร้อมเหตุผลได้ ข้อมูลพนักงาน การลา วันหยุด และวันหยุดบริษัทแสดงจากรายการต้นทางในช่องอ่านอย่างเดียว หลังแก้ต้องอนุมัติใหม่ ค่า OT เริ่มต้นยังลงที่ 1.5x และคำนวณใหม่เมื่อเปลี่ยนเวลาโดยเลือกช่องคำนวณอัตโนมัติ หัวหน้าแผนกและ OWNER แก้ได้; OWNER ลบรายการลงเวลาได้โดยมีเหตุผลบันทึกใน AuditLog
- พนักงานและหัวหน้าแผนกยื่นคำขอลาได้ OWNER ไม่ยื่นคำขอลา หัวหน้าแผนก/OWNER พิจารณาคำขอได้ Admin เพิ่มและแก้ LeaveTypes ได้ในหน้าตั้งค่า
- ในหน้าปฏิทิน พนักงานและหัวหน้าแผนกยื่นคำขอลาด้วยวันเริ่มและวันสิ้นสุดได้ คำขอวันหยุดก็ใช้วันเริ่มและวันสิ้นสุดในคำขอเดียว โดยปฏิทินแสดงทุกวันที่อยู่ในช่วงนั้น
- พนักงานขอวันหยุดได้เฉพาะตนเอง คำขอจะอยู่ในสถานะรออนุมัติจนหัวหน้าแผนกหรือ OWNER พิจารณา Admin สามารถกำหนดวันหยุดให้ผู้อื่นได้ พนักงานแก้หรือยกเลิกคำขอวันหยุดของตนเองได้ และแก้หรือยกเลิกวันลาของตนเองได้ เมื่อแก้รายการที่เคยอนุมัติแล้วต้องรออนุมัติใหม่
- ปฏิทินแสดงเฉพาะชื่อในสีสถานะ: เขียว = มาทำงาน, แดง = วันหยุดที่อนุมัติแล้ว, เทา = ลาที่อนุมัติแล้ว วันที่ไม่มีรายการยังไม่กำหนดสถานะ
- OWNER เปิดหรือปิดการบังคับตรวจโลเคชันใน **ตั้งค่าระบบ → LOCATION** ค่าเริ่มต้นคือเปิด เมื่อปิด พนักงานสแกนจากทุกที่ได้ และระบบไม่ขอพิกัดขณะลงเวลา
- Admin ตั้งค่าพิกัดละติจูด ลองจิจูด และรัศมีใน **ตั้งค่าระบบ → LOCATION** (Config: `Target Latitude`, `Target Longitude`, `Allowed Radius (KM)`) ระบบขอตำแหน่ง GPS และตรวจว่าอยู่ในรัศมีก่อนเปิดกล้อง รวมทั้งตรวจซ้ำที่ Apps Script ขณะเทียบใบหน้าและก่อนบันทึกเวลา หากปิดสิทธิ์ตำแหน่ง ตำแหน่งคลาดเคลื่อนเกินรัศมี หรืออยู่นอกพื้นที่ ระบบจะไม่บันทึกเวลา ควรตั้งพิกัดสถานที่ทำงานจริงก่อนเผยแพร่
- Admin ส่งออก CSV รายวันจาก **ประวัติและรายงาน** โดยเลือกช่วงวันที่ รายงานมีทุกคนในแต่ละวันและแยกทุกรอบเข้า–ออก รวมสถานะมาทำงาน/ลา/หยุด/วันหยุดบริษัท เวลาเข้าออก OT ประเภทและสถานะคำขอ ช่วงส่งออกสูงสุด 366 วัน
- หน้าตั้งค่าของผู้ที่เข้าสู่ระบบไม่แสดงเมนูเชื่อมต่อ Apps Script; ตั้งค่า URL ได้เฉพาะก่อนเข้าสู่ระบบ
- หน้าเข้าสู่ระบบมีตัวเลือก **จำการเข้าสู่ระบบบนเครื่องนี้** ที่เก็บ session token อายุสูงสุด 6 ชั่วโมงและรหัสพนักงานในเบราว์เซอร์ PIN อาจถูกบันทึกโดย password manager ของเบราว์เซอร์เมื่อรองรับ แอปไม่บันทึก PIN เป็นข้อความใน localStorage

## ข้อมูลใบหน้าและข้อจำกัด

`FaceTemplates` เก็บเวกเตอร์ตัวเลข 128 ค่าเป็น JSON ต่อพนักงานพร้อมสถานะและเวลาลงทะเบียน ไม่เก็บภาพถ่ายต้นฉบับ ทุกเครื่องอ่านชีตเดียวกันผ่าน Apps Script และการบันทึกเวลาใช้ LockService ป้องกันรายการชนกัน จำกัดสิทธิ์ Google Sheet ให้เฉพาะผู้ดูแล เพราะเวกเตอร์ใบหน้าเป็นข้อมูลอ่อนไหว

ระบบยังไม่มีการตรวจภาพปลอม/วิดีโอ (liveness) และ API หน้าสแกนร่วมไม่ต้องล็อกอิน ผู้ที่ได้เวกเตอร์อาจส่งซ้ำได้ จึงไม่ควรใช้เป็นหลักฐานยืนยันตัวตนที่มีความเสี่ยงสูงโดยไม่เพิ่มมาตรการป้องกัน การตรวจตำแหน่งผ่านเบราว์เซอร์อาศัยพิกัดที่อุปกรณ์ส่งมา จึงป้องกันการสแกนทั่วไปนอกพื้นที่ได้ แต่ไม่ป้องกันการปลอมพิกัดระดับอุปกรณ์ กล้อง เสียง และ GPS จริงต้องทดลองบน HTTPS ของอุปกรณ์ที่จะใช้ face-api.js และโมเดลโหลดผ่าน jsDelivr จึงต้องออนไลน์

## ตรวจระบบ

จากโฟลเดอร์ที่แตก ZIP:

```sh
node tests/backend-smoke.cjs
node tests/ui-smoke.cjs
node tests/face-smoke.cjs
node tests/api-smoke.cjs
```

ชุดนี้จำลอง Google Sheets และกล้องเพื่อทดสอบเส้นทางหลัก ยังต้องตรวจกล้อง เสียง สิทธิ์เบราว์เซอร์ และ Web App/Google Sheet จริงหลัง Deploy
